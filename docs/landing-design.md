# LifeInbox 3D 소개 페이지 설계

## 구성과 경계

`apps/landing`은 Vite·TypeScript로 만드는 독립 정적 앱입니다. 기존 `apps/web`의
Dashboard·인증·API 중계와 `apps/api`의 서비스·DB 연결을 유지합니다.
DB는 현재 revision 0007을 유지하며 추가 테이블·마이그레이션·공개 데이터 API는 없습니다.

```text
apps/landing/
  index.html              의미 있는 본문과 화면 예시; JavaScript 없이도 읽을 수 있음
  src/main.ts             장면 초기화, 대체 화면, 수명 관리
  src/styles.css          반응형 레이아웃과 제품 화면 예시
  src/scene/model.ts      카드와 수납 트레이의 실제 3D 모델
  src/scene/renderer.ts   카메라·조명·렌더러, 해상도와 가시성 관리
  src/scene/story.ts      구간별 오브젝트 배치
  src/scroll.ts           Anime.js 타임라인·ScrollObserver, 본문 등장
  public/                 자체 제작 SVG 로고와 정적 대체 일러스트
e2e/landing/              소개 페이지의 브라우저 테스트
```

## 이야기와 표현

밝은 미색 배경, 현재 앱의 녹색 계열, 넓은 여백과 큰 한글 제목을 사용합니다.
메시지는 “흩어진 생활 정보, 하나의 Inbox로.”입니다.
하나의 장면이 수집 → 개인·업무·공유 공간 → OCR 확인 → 규칙 분류 → 일정·결제 →
검색 → 완성된 Inbox로 변화합니다. 직접 모델링한 카드·트레이에 실제 두께와 조명·그림자를 줍니다.
제트엔진이나 외부 사이트의 에셋은 복제하지 않습니다.

본문과 앱 형태의 화면 예시는 HTML·CSS로 만들며 모두 합성 데이터입니다.
‘예시 화면’을 표시하고 실제 계정·사용자 항목·이미지를 쓰지 않습니다.
OCR은 원본 보존·필드 확인·수정 후 추가, 자동화는 현재 구현된 규칙·범위·기록을 설명합니다.
주요 링크는 기능 살펴보기, GitHub, README의 로컬 실행 안내입니다.

## 스크롤과 성능

본문은 브라우저 기본 스크롤로 이동하고, 전체 이야기의 진척도를 Anime.js 타임라인에 연결합니다.
모델의 배치·회전과 포인터 기울기는 별도 Group에서 합성합니다. 빠른 스크롤·역방향·해시 이동도
같은 진척도에서 동일한 장면을 만들고, 리사이즈하면 현재 위치에서 다시 측정합니다.
타임라인은 스크롤 위치에 직접 동기화하고 각 장면 사이의 포즈를 보간합니다.
렌더링 프레임 수가 적은 환경에서도 장면이 스크롤 위치를 뒤늦게 따라잡지 않도록 합니다.
데스크톱은 텍스트 왼쪽·모델 오른쪽, 모바일은 모델 위·본문 아래로 배치합니다.

3D 코드는 동적 import로 분리합니다. DPR은 데스크톱 최대 1.5, 모바일 최대 1이며
보이지 않는 장면과 숨겨진 탭에서는 렌더링을 멈춥니다. 도형과 재질을 재사용하며 종료 시
Anime 인스턴스·이벤트·관찰자·GPU 리소스를 정리합니다.
모션 감소·WebGL 실패에는 정적 SVG를 보여줍니다. 초기 본문을 CSS로 숨기지 않습니다.

## 게시

공개 저장소는 `movenb3at/LifeInbox`, 기본 브랜치는 main,
Pages 주소는 `https://movenb3at.github.io/LifeInbox/`, base는 `/LifeInbox/`입니다.
Pages에는 소개 페이지 dist만 배포합니다. PR에서는 검사·빌드, main 푸시와 수동 실행에서는
검사·빌드·배포를 수행합니다. 공식 Actions를 SHA로 고정하고 배포 job에만 Pages 쓰기 권한을 줍니다.
기존 Supabase 헬스체크는 동일 저장소의 변수·Secret으로 매일 한국 시간 09:17에 실행합니다.
환경변수·캐시·DB 데이터·OCR 모델·빌드 산출물을 공개 커밋에서 제외합니다.

## 완료 검증

소개 페이지 타입·린트·빌드, 실제 3D 렌더링, 각 장면의 스크롤·역방향·해시 이동,
리사이즈·모바일·키보드·모션 감소·WebGL 실패·JavaScript 비활성화·하위 경로를 검증합니다.
기존 앱의 전체 회귀 검증을 수행하고 실제 Pages URL과 수동 헬스체크 실행까지 확인합니다.
